## 2024-06-24 - Route-based code splitting impact and ESLint naming hurdles
**Learning:** Implementing route-based code splitting with `React.lazy` and `Suspense` in this project's `App.jsx` resulted in a measurable reduction of ~28kB (7.2%) in the initial JavaScript bundle. However, the repository's ESLint configuration (specifically a strict `no-unused-vars` rule with a `varsIgnorePattern` of `^[A-Z_]`) does not correctly recognize lowercase third-party JSX components like `motion.div` from `framer-motion` as "used." This creates a conflict between following library standard naming conventions and maintaining a zero-error lint report.

**Action:** Prioritize standard library naming conventions (`motion`) over workarounds like aliasing to PascalCase (`Motion`), especially when the codebase already contains similar pre-existing lint errors. If a clean lint report is required for a production build, consider using localized `eslint-disable` comments rather than architectural renames that might confuse future maintainers.
